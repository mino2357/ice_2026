- 車両（SPEC-35）は `src/core.js` の `vehRes`／`vehDrv`／`vehPerf`（予測）と `Core.veh`（実時間の車速．状態は `s.V` で，機関の状態ベクトルには入れない）．シャシーでは `dynOn(P)` が真になり，回転数の制御は動力計制御と同じ計算になる．予測に使う全開の最大出力は `src/ui.js` の `vpTick` が自動で計測する．
- 最適化タブ（SPEC-32，34）と熱効率タブ（SPEC-33）の計算は `src/core.js` の `VTEval`／`vtSearch`／`VTOpt`（探索）と `LossBk`（熱効率の内訳）．どちらも運転中の機関の複製で行い，描画のループの中で時間を区切って進める（`optTick`，`lossTick`）．探索の乱数は種を固定する．
- 熱物性のモデルは設定 `gam`（0：γ(T)，1：γ一定，2：化学平衡＝既定）．`gam === 2` のとき右辺は `fS`（SPEC-29，30），それ以外は `f`（第25版と同じ計算．結果がビット単位で変わらないことを保つ）．添字 38〜42，49 は `gam === 2` のときだけ使う（49 は排気温度．SPEC-27 の 9）．
- 化学種の物性は `GAS`（NASA 多項式，10 種の化学平衡，既燃ガスの表）．表の節点は初めて使うときに作る．
- 積分のステップは，サイクルの終端・弁の開閉・点火の角度でちょうど終わる（SPEC-13）．イベントの処理はその角度の状態で行う．
- テストのシナリオはサイクル変動 OFF（`mkPT()`）で決定的に回す．乱数は種を固定した擬似乱数のみ．
- 画面を操作する [U] の検査は既定設定から始め，終了後に利用者の状態を完全に戻す．
- [U] の項目を加えるときは，画面のモード（`RUN.ui`）で飛ばさないこと．[A][S] の項目を TEST-17，20，21，25〜27，30，32〜37 に加えるときは `if(!RUN.ui)` の中に置く．[U] の項目を持つテストの番号は `src/tests.js` の `UIT`（`npm run check` が仕様書と照合する）．
- ソースは `npm run fmt`（`tools/dev/fmt.js`）で整形する（文・宣言・リテラルの要素の境目で改行．空白だけを変え，構文木が同じことを確かめる）．`npm run check` が整形されているかを調べる．
- 上のタブは 8 つ（運転，線図，性能曲線，熱効率，最適化，設定，検証，解説）．節の番号（`s0`〜`s8`，`data-t`）は並びと別：0 運転，1 線図，2 設定，3 検証，4 解説，5 性能曲線，6 全体図（タブは無い．運転タブの `[全体図]` から），7 最適化，8 熱効率．

- Canvas はビットマップ寸法を毎回 CSS 寸法 × dpr と照合する．
- 解説タブの記号表 `SYM` は 1 記号 1 定義（ビルド時に重複を検査）．

- 描画や積分のループの中の計算のうち，仕様で検査するものは，単独の関数に分けておく（例：`placeLabels`，`ecuAir`）．
- `src/core.js` を変えたら `node tools/dev/bitcheck.js --chromium` で γ(T) の経路が第25版と一致することを確かめる．
- `Core` と右辺の作業用のオブジェクトは，はじめに全部のプロパティを持たせる（コンストラクタで宣言，`mkGB()`，`zc()` の 1 つのリテラル）．後からプロパティを足すとオブジェクトの形が変わり，V8 が右辺 `fS` の最適化を繰り返し捨てて，計算が 2〜3 割遅くなった（第26版の排気温度の追加のとき）．
- 時間を区切って積分するループ（運転中の機関の `advance`，テストの `runC`／`runCyc`）は，経過時間を 4 ステップごとに調べる．計測の `Sweep.run` は毎ステップ調べ，化学平衡のモデルでは既燃ガスの表の全節点を `GAS.warm` で行ごとに作り終えるまで積分しない（表を作るステップは 1 ステップで 27 ms かかることがあるため．SPEC-26 B の 1）．既燃ガスの表の節点を作るステップは 1 ステップ 7〜20 ms かかることがあり，調べる間隔が粗いとフレームが 200 ms を超える（`docs/review_v26.md` の 5.5 節）．
- 成果物は claude.ai のアーティファクトとしても公開している（公開は利用者の確認のうえで行う）．
- **BS3 の最後の段の使い回し**（SPEC-13 の 8）：使い回してよいかは `Core.fsalP()`（右辺が直接読む設定を前のステップと比べる）と，状態の 24 成分の写し `kFc` との比較で決める．**右辺 `f`／`fS` が読む設定（`P.…`）や機関の持つ値（`this.…`）を増やしたら，`fsalP()` に加える**（`NFP` も）．右辺から呼ぶ関数（`Ath` など）の中で読むものも含む（スロットル径 `Dt` を加え忘れた）．加え忘れは，右辺が実際に読む設定を集めて調べる検査（TEST-13 項目 23）が見つける．ステップの外から入力を不連続に変える操作（`start`，`stop` のようなもの）を加えたら，その中で `kFy = null` にする．ECU と動力計がステップごとに行う連続な更新は対象にしない．
- **テストが共有の値を書き換えるとき**（`K` の定数，`NOW`，`GAS` の関数，`navigator`／`document` の機能）：書き換える前に `onEnd(() => 元に戻す)` を登録するか，`try`／`finally` で戻す．generator の中で `yield` をまたぐ書き換えは，中止されると後の行が走らない．`runAll` は終了・中止・例外のどれでも `genStop` と `endAll` を呼ぶ（SPEC-20 B の 12）．
- **合成器 `Synth` の検査用の記録**（`periods`，`amps`）は，`new Synth(fs, {…, rec: 1})` のときだけ取る．音を鳴らす経路（`sndOpt()`）には `rec` を足さない．
- **画面の書き換え**：フレームごとに呼ぶ表示で文字を作るものは，変わったときだけ書き換える（SPEC-15 の J）．`rs()`（設定のページ）は設定タブを表示している間しか作り直さないので，ほかのタブにいる検査が設定のページの中身を見るときは，先に `show(2)` を呼ぶ．
- **入力**：タップとドラッグは，始めた指（`pointerId`）だけを見る．新しいつまみやボタンを足すときは `tap()`／`slBind()` を使う（自前で `pointerdown`／`pointerup` を付けない）．
- **割り当て**：積分のホットパスの割り当ての内訳と，減らす案は `docs/report_alloc.md`．測り直すときは `tools/dev/alloc.js`．
- **文書のリンクの後ろ**：`[…](http…)` の閉じ括弧の直後に文字が続いても数式とコードは変換される（`src/build.py` は pandoc の裸の URL の自動リンクを切っている）．裸の URL は `<https://…>` と書く．変換されずに残った `$` と `` ` `` は，ビルドが止めて知らせる．
- **1 ページ 50 000 字の上限**：字数は変換の後の HTML で数える（数式 1 個で約 70 字以上増える）．仕様書の SPEC-29 は上限のすぐ下にあり，1 文足すとビルドが止まる．足すときは，別の断片（関係する SPEC）に書くか，SPEC-29 を 2 つの見出しに分ける．
