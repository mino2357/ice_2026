# テストの所要時間の内訳（2026-11-23）

利用者の指示「遅すぎないか？なぜ遅いのか．原因を特定して」による調査．計測の間は，同じ計算機で別の重い処理を走らせていない．

## 環境

* 開発用の計算機（WSL2，8 コア，メモリ 11 GB）．ヘッドレスの Chromium 153，`tools/dev/run.js`．
* 成果物は commit `8972ce4` の直前の作業ツリー（C-4 を入れた状態）．

## 2. フレームごとの計算の予算

テストは 1 フレームに $12\ \text{ms}$ だけ計算して次のフレームを待つ（`RUN.over`．画面が固まらないように）．計算に使えるのは最大で約 $72\%$（$12/16.7$）．予算だけを $200\ \text{ms}$ にした写しで，上位のテストを単独で実行して比べた．

| テスト | 予算 12 ms [s] | 予算 200 ms [s] |
| :--- | ---: | ---: |
| TEST-26 | 59.4 | 52.1 |
| TEST-32 | 63.6 | 53.3 |
| TEST-34 | 65.2 | 59.1 |

* 予算による差は $10$〜$16\%$．待ち時間は主な原因ではない．
* TEST-37 の行は出力に無かった（`--time` の集計の最後のテストが落ちる．道具の不具合の可能性．確かめていない）．

## 3. 全項目の中で実行すると遅くなる

同じテストを単独で実行したときと，全項目の中で実行したときで，所要が大きく違う．

| テスト | 単独 [s] | 全項目の中 [s] |
| :--- | ---: | ---: |
| TEST-32 | 63.6 | 90.0 |
| TEST-34 | 65.2 | 101.3 |
| TEST-26 | 59.4 | 69.2 |

* 全項目の中では $1.2$〜$1.6$ 倍遅い．前のテストが残したもの（メモリ，表，DOM，キャッシュ）による可能性がある（推定．原因は調べていない）．

## 4. 並列にしていない

* テストは 1 つのブラウザの 1 つのページで，順に 1 本で実行している．計算機は 8 コアあるが，使っているのは 1 コアだけ．
* `src/core.js` は DOM に依らないので，機関の計算だけの検査は Node.js でも動く（`tools/dev/bitcheck.js` はそうしている）．

## まとめ（推定を含む）

* 主な原因は，(1) 機関のサイクルを多数回す検査が多いこと（計算そのもの．1 サイクル約 $9\ \text{ms}$），(2) 1 コアで順に実行していること，(3) 全項目の中で後のテストほど遅くなること．(4) フレームごとの待ちは $10$〜$16\%$．
* (1) は本質的な計算量だが，(2) と (3) は進め方の問題で，変えられる．

## 5. 組に分けて同時に実行した結果（2026-11-24）

* 全項目を所要時間の実測で 4 組（各約 $214\ \text{s}$ の見込み）に分け，`run.js` を同時に 4 本実行：全部 PASS，壁時計 $440\ \text{s}$（1 本では $855\ \text{s}$．$1.94$ 倍速い）．計算機は 4 コア 8 スレッド．
* 段階 1 の全項目はこの形にした（`tools/dev/shard.js`）．性能の記録は同時の実行で値が変わるので，段階 1 では判定しない（今までどおり）．
