# 調査の記録：積分のヒープの割り当てと，流量関数の折れ目でのステップの棄却（2026-11-22〜23）

外部のレビュー（`docs/changes/2026-11-22-review-gemini-1.md`）の H-1（割り当て）と H-4 の 1（$\Psi$ を $C^1$ にする案）を判断するための実測．実装は変えていない．数値はすべてこの PC（WSL2，Core i5-8350U，Node.js 22.23.5）で実行して得た．

## 1. 割り当て

### 1.1 測り方

`tools/dev/alloc.js`（新設）．全開・$3000\ \text{rpm}$ 固定，サイクル変動 OFF，30 サイクル．

```
node --expose-gc --max-semi-space-size=64 tools/dev/alloc.js 30
```

* **内訳**：V8 の標本のヒーププロファイラ（`HeapProfiler.startSampling`，標本の間隔 64 バイト，GC で回収されたものも数える）で，割り当てた関数ごとのバイト数．
* **合計の照合**：GC の起きない 100 ステップの区間の `heapUsed` の増分．既定の構成では $4164\ \text{B}$/ステップで，プロファイラの合計 $4184\ \text{B}$/ステップと合った．ほかの構成ではこの方法の値がばらついた（表の節点を作る割り当てが混じるためと見られる．推定）ので，下の表はプロファイラの値だけを使う．
* **1 つ外したときの差**：読み込む前にソースを書き換えて（`alloc.js` の 3 つ目の引数），割り当てを 1 つ外したときの減り方を見た．成果物は変えていない．

### 1.3 分かったこと

1. **いちばん大きいのは `this.X`**（表示・集計用の 36 項目のオブジェクトと，その中の `k`）で，全体の約 45 %．BS3 では 1 ステップに 1 回（最後の段），使い回せないステップではもう 1 回作る．値が浮動小数点数の項目は，項目ごとに数値の箱も作る（推定．減った量が，オブジェクト 1 個の大きさより大きいことから）．
2. **`bs3c` の `y3`** が約 13 %，**`step` の `vals`**（18 要素の配列）などが約 7 %．
3. 残りの約 35 %（約 $1.5\ \text{kB}$/ステップ）が，関数の引数と戻り値の数値の箱と見られる（推定．右辺の残り $841$，`bs3c` の残り $234$，小さい関数の合計 約 $320$）．
4. **サイクルごとの割り当て**（`cycleEnd` の `Float32Array` 3 本の写し $17.3\ \text{kB}$ と `y.slice()`）は，1 サイクル $2.26\ \text{MB}$ の $1\ \%$ に満たず，プロファイラの表に現れない．
5. **要件定義書 7.2 節の 24 の推定は，量は合っていて，内訳が違っていた**．「右辺 `fS` は 1 回に約 $440$ バイト（1 ステップに約 $4\ \text{kB}$）」の合計は実測（$4.2\ \text{kB}$/ステップ）と合う．しかし「インライン化されない関数の呼び出しの引数と戻り値の数値の箱と見られる」は一部（約 35 %）で，約 65 % は明示的に作っているオブジェクトと配列（`this.X`，`y3`，`vals`）だった．レビューの H-1 の指摘のうち，`bs3c`／`step` の割り当てが主な源という点は正しく，`cycleEnd` の写しが大きいという点は当たらない．
6. **GC の停止が減るかは測っていない**．7.2 節の 24 の停止（major GC $26.4\ \text{ms}$）は，それまでのテストで大きくなったヒープの生きているオブジェクトの量で決まる（その記録の読み取り）．割り当てを減らすと major GC の回数は減るが，1 回の停止の長さが短くなるとは限らない．

### 1.4 割り当てを減らす案（実装していない．利用者の判断を待つ）

## 2. 流量関数の折れ目とステップの棄却

### 2.1 測り方

`tools/dev/kink.js`（新設）．BS3 の 1 回の試行（`bs3c` の 1 回の呼び出し．2〜4 段目の 3 回の右辺）の中で，流量関数 $\Psi$ の評価が，直線の側（$r_p > 1 - \delta_r$，$\delta_r = 10^{-3}$）と，すぐ外側（$1 - 3\delta_r < r_p \le 1 - \delta_r$）の両方にあった試行を「折れ目をまたぐ」，どちらかがあった試行を「近く」，どちらも無い試行を「遠い」とし，棄却（誤差の見積もり $E > 1$）の率を比べた．どのオリフィスかは区別していない（別のオリフィスが片側ずつでも「またぐ」に数えるので，多めに数える側）．40 サイクル．

```
node tools/dev/kink.js 40
```

### 2.2 結果

| 条件 | ステップ/サイクル | 棄却（全体） | またぐ試行の割合 | またぐ試行の棄却率 | 遠い試行の棄却率 | 棄却のうち，またぐ試行 |
| :--- | ---: | ---: | ---: | ---: | ---: | ---: |
| $800\ \text{rpm}$・開度 $6^\circ$（回転数固定） | 1725 | 1.58 % | 4.27 % | 20.65 % | 1.49 % | 55.7 % |

強制受理（誤差が許容を超えたままの受理）はどの条件でも 0 回．

### 2.3 分かったこと

1. **折れ目をまたぐ試行は，確かに棄却されやすい**（棄却率 $8$〜$40\ \%$．遠い試行は $1.5$〜$4.6\ \%$）．レビューの指摘（折れ目で誤差の次数が落ちる）と合う．
2. **しかし，全体への効きは小さい**．棄却は全試行の $1.6$〜$4.3\ \%$ で，そのうち折れ目をまたぐ試行は $19$〜$56\ \%$．折れ目による棄却をすべて無くせたとしても，減る試行は全体の $0.8$〜$1.1\ \%$（$4.27\ \% \times 20.65\ \% = 0.9\ \%$ など）にとどまる．棄却の後で刻みが小さくなる分の損は，この数え方には入っていない（測っていない）．
3. **見立て**：$\Psi$ を $C^1$ にしても，右辺の評価の回数は $1\ \%$ 前後しか減らない見込みである．一方で，`psiF`／`psiC` は $\gamma(T)$ の経路も使うので，変えると第25版とのビット一致が崩れる（化学平衡の経路だけ変えると，オリフィスの式が 2 通りになる）．**採らないことを勧める**．判断は利用者．
