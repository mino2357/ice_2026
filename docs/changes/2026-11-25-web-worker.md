# 2026-11-25 重い計算を Web Worker で行う（朝の判断の 12 (c)）

## 指示

朝の判断の 12（`docs/changes/2026-11-24-review-gemini-6.md`）：「(c) 重い計算を Web Worker へ（要件の差分を見せる）」．利用者の「はい」で着手した．

## 先に確かめたこと

* claude.ai のアーティファクトの中で Blob の URL から Worker を作れるか：確認用のページ（https://claude.ai/artifact/QoVCKvj1qYe2dJZK8DPUDR）を公開し，利用者がスマートフォンの claude.ai で開いて「成功」を確かめた．手元のヘッドレス Chromium（`file://`）でも作れ，速さはメインスレッドと同じ，その間のフレームの間隔の最長は $42\ \text{ms}$ だった．

## 要件の差分（承認済み 5d42512）

* REQ-15 の 17 を足した：重い計算（性能曲線の計測，シャシーでの車両の最高出力の掃引，運転点のマップ，弁時期の探索，VVT マップ）は，Web Worker が使えるときは別のスレッドで行う．(a) 結果はメインスレッドと完全に一致，(b) メインスレッドがその計算に使う時間は 1 フレームあたり $2\ \text{ms}$ 以下，(c) 途中の経過の表示と `[中止]` は同じに働く，(d) Worker が使えない・失敗したときはメインスレッドで進め，結果は同じ．熱効率の内訳はメインスレッドのまま．

## 決めたこと

* 仕様：SPEC-15 L（Worker の作り方，始め方，進め方，写し方，終わり，使えないとき，同じ結果）．検査：TEST-15 項目 22．用語の定義集 3.4（Web Worker，写し）．6 節の対応表．
* **Worker の作り方**：ビルドで `src/core.js` を `id="coresrc"` の `<script>` に分け，その本文に `wkMain()` の呼び出しを足して Blob の URL から Worker を作る．同じ計算のコードを使うので結果が同じになる．Worker は 1 つで，ページを閉じるまで使い回す．
* **画面の側**：計算のオブジェクトはこれまでどおり作り（画面が作った直後から読む値のため），`run` だけを Worker の写しを写すものに替える．画面のコード（表示，描画）はほとんど変えていない．運転中の機関を引数にとる探索と VVT マップは，始めた時点の `clone()` を控えて送る．
* **写し方**：一番上の欄の配列と素のオブジェクトは中身を入れ替え（`OP.h` などの別名を保つ），要素は届いたものをそのまま使う．はじめは入れ子まで中身を入れ替えたが，`VTOpt` の履歴の点が違った（Worker の中で途中から別々になった配列を，1 つに上書きした）ので改めた．
* **使えないとき**：はじめは「控えたデータの欄に戻してメインスレッドで進める」案にしたが，性能曲線の計測の中の `pts` の別名（`sets[k].pts` と，中の `Sweep` の `pts`）が写しで切れるので，始めたときの引数で作り直したものをメインスレッドで進め，毎フレーム同じ写し方で写す形にした．
* **変わった欄だけを送る**：はじめは毎回すべてのデータの欄を送っていた．段階 1 で TEST-35（車両の最高出力の自動の計測が $20\ \text{s}$ 以内に終わる）が FAIL した．原因：`Sweep` は自分でも `sig`（引数の JSON）を持ち，画面が作った直後に書く設定の印 `VP.run.sig` を写しが上書きしたので，`vpTick` が毎フレーム計算を作り直していた．Worker は前に送ったときから変わった欄（欄ごとの JSON で比べる）だけを送るようにした．TEST-15 項目 22 に「画面が書いた `sig` が上書きされない」を足し，成果物の写しで送り方だけを元に戻すと，TEST-15 と TEST-35 が FAIL することを確かめた．
* **外れた計算を終える**：検査が `OP.vm=null` のように計算を直接捨てると，Worker の中にその計算が残り，ほかの計算と交互に進んで遅らせる．新しい計算を始めるとき（`wkJob`），画面の欄（`SW.run`，`MP.run`，`VP.run`，`OP.run`，`OP.vm`）から外れた計算を終える（`wkGc`）．
* 熱効率の内訳（`LossBk`）は対象外：運転中の機関から毎秒作る小さな計算で，1 フレームの持ち時間 $6\ \text{ms}$ で足りている．

## 検証の結果

* **TEST-15 項目 22**（単独）：4 件とも PASS．5 種類とも Worker の結果がメインスレッドと一致（比べた JSON は $2216$〜$16714$ 字），メインスレッドの `run` の 1 回の最大 $0.40\ \text{ms}$，`wkEnd` の後の写しは使わない，`U.noWk` と Worker の中の例外でメインスレッドに移って同じ結果．
* **検査が直す前に FAIL すること**：実装を外した写し（HEAD の作業ツリーに新しい `src/tests.js` だけを置いた）で，TEST-15 が「例外: WK is not defined」で FAIL した．
* 途中の FAIL：比べる値に経過時間 `t` のほか 1 回の持ち時間 `ms`（`OpMap`，`VVTMap` が持つ）が入っていて違った（Worker の中は $20\ \text{ms}$，検査は $10\ \text{ms}$ で進めた）．計算の結果ではないので比べる値から外した．`VTOpt` の違いは上の写し方の不具合で，直した．
* **速さ**（ヘッドレス Chromium，開発用の計算機，既定の性能曲線の計測 28 点，運転中）：Worker $2.95$，$2.99\ \text{s}$，メインスレッド $6.59$，$8.81\ \text{s}$．メインスレッドがこの計算に使う 1 フレームの時間の最大：Worker $0.4\ \text{ms}$，メインスレッド $9.4$〜$10.7\ \text{ms}$．
* **段階 1**（`npm run verify`）：ビット比較が一致，全項目 635 件中 FAIL 0 件（所要 $234\ \text{s}$），画面のモード（$820 \times 1180$）228 件中 FAIL 0 件．はじめの実行では TEST-35 が FAIL した（上の「変わった欄だけを送る」で直した）．
* **省かない実行**（段階 1 で省く重い検査のうち，画面から Worker を使うもの．`run.js --only 26,32,34,37`）：67 件中 FAIL 0 件．性能の記録の上限超えは TEST-34 の VVT マップの計算の所要（$54.6\ \text{s}$，上限 $40\ \text{s}$．検査の中で `VVTMap` を直接メインスレッドで計算する値で，この変更の対象外．判定しない）．
* 段階 2 は実行していない．
