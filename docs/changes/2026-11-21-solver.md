## 決めたこと

利用者の指示（「A」）で実装した．

1. **既定の解法を BS3(2) にした**（設定「ソルバ」の 3 つ目の選択肢，既定）．最後の段の使い回し（FSAL），刻みの PI 制御，刻みの上限 $5^\circ$ と $2\ \text{ms}$（仕様書 SPEC-13 の 8）．DOPRI5 と RK4 は設定で選べる．
2. **相対許容誤差は $4 \times 10^{-5}$**．調査で勧めた $3 \times 10^{-4}$ は，定常の平均では基準を満たすが，同じ状態から進めた 1 サイクルでは低負荷で当量比が $1.1\%$ ずれることが，実装のテストを書くときに分かった（レポートの 8.1 節）．1 サイクルの差で選び直した．右辺の評価の回数は DOPRI5 の $0.24$ 倍（調査の見積もりは $0.17$〜$0.20$ 倍）．
3. **要件の差分**（承認待ち）：受入基準 11 に「同じ状態から進めた 1 サイクルの差」と「回転数が自由な運転」を加え，12 の値を「$1/2$ 以下（目標）」から「$0.3$ 倍以下」に確定し，16（線図の記録に抜けが無い）を加えた．
4. **テストのシナリオは DOPRI5 のまま**（`mkPT()` に `sol: 1`）．600 件近い判定値は DOPRI5 で求めたもので，モデルの式の検査である．既定の解法の精度は，TEST-13 項目 14〜21 で DOPRI5 の参照解と比べて確かめる（仕様書 SPEC-20 C）．画面を操作する検査（[U]）は，運転中の機関（既定の BS3）で動く．
5. **線図の升**：BS3 は刻みが $0.5^\circ$ より大きいので，ステップの間を線形に補間して升を埋める．
6. **最後の段の使い回しと制御の入力**：使い回す右辺は，ECU と動力計の更新の前の入力での値である（入力の変化は次のステップの 2 段目から効く．仕様書 SPEC-13 の 8）．
7. **互換**：DOPRI5 を選ぶと，解法を加える前のコード（commit `93f480b`）と状態の全成分がビット単位で同じ（`tools/dev/bitcheck.js` に比較を加えた）．アプリの中の検査は相対 $10^{-6}$（JavaScript の処理系で丸めが違うため）．
