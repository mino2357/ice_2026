## 行わなかったもの（理由）

* **`docReveal` の強制レイアウトの削除**（レビューの Low の 2）：行わない．1 要素を表示するたびにレイアウトを確定させているのは，1 フレームの持ち時間 $8\ \text{ms}$ にレイアウトの時間を含めて数えるためで，外すと残りの要素を 1 フレームで全部表示し，1 回の長いレイアウトでフレームが止まる（コードを読んだ判断．測ってはいない）．SPEC-15 の J の 3 に意図を書いた．
* **`MutationObserver` の `attributeFilter`**（Low の 4）：はじめ「どの属性が変わるか確かめられない」として行わなかったが，色を決める `src/style.css` が見る属性は `data-theme` だけなので，後で `['data-theme']` に絞った（2026-11-23）．
* **フレームの予算の共有**（H-2 の 1）：行わない（計測のジョブを同時に走らせたときの挙動が変わる．要件の判断が要る）．朝の判断待ち．
* **`Core` の割り当ての削減**：実測と案まで（`docs/report_alloc.md` の 1.4 節）．

## 後で見つかった誤り（2026-11-23．第 4 群の後の段階 1）

この群のコミット（`d55d01c`）の `rs()` の早期の戻りは，性能曲線の「前提」の表の更新（`rs()` の末尾の `swFresh()`）まで飛ばしていた．関係するテストとして TEST-15，18，22，23，36 だけを実行してコミットしたため見逃し，第 4 群の後の段階 1 の全項目で，TEST-26 の「前提画面：設定の変更を即座に反映」が FAIL した（1 件）．`rs()` は，設定タブを表示していないときも `swFresh()` を呼ぶように直した（第 4 群のコミットに含めた）．TEST-15，18，23，26 を実行して FAIL 0 件を確かめた．

* 原因：`rs()` の副作用（設定のページのほかに何を更新するか）を，関数の末尾まで読まずに決めた．影響するテストを自分で選んだ．
* 対策：選んだテストだけでコミットしない．`npm run verify -- --plan` が示す範囲（`src/ui.js` を変えたら全項目）を実行してからコミットする（`CLAUDE.md` の作業の進め方の 12 に加えた）．
