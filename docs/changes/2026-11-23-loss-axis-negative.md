# 2026-11-23 熱効率の図で，熱効率が負のときの横軸

## 指示

利用者（先行版の熱効率タブの図へのコメント）：「熱効率マイナスになったら位置がおかしい．軸が 0 からの表示になってる．直して」．

## 要件の差分

なし．REQ-33 の画面の表示の範囲の不具合として，画面の文書 SPEC-33 C の 1 に横軸の範囲を書き足し，TEST-33 に項目 8 を加えた．

## 決めたこと

* 原因：`lossSpec`（`src/plot.js`）は，横軸を $0$ から理論の熱効率の切り上げまでとし，位置の関数で負の値を `Math.max(0, v)` で $0$ に丸めていた．アイドルなどで正味熱効率（や正味の図示熱効率）が負になると，棒と値が $0$ の位置に貼り付いた．
* 直し方：横軸を，$0$ と全段の値を含む $10\ \%$ 刻みの範囲にする（負の値があれば負の側にも伸ばす）．$0$ の線は目盛りの線より濃い色にする．目盛りと値の負の符号は「−」．

## 検証の結果

* **テストを先に**：TEST-33 項目 8（S4 の結果の正味熱効率を $-10\ \%$ にした配置）は，直す前の成果物で FAIL（$0$ の線が図の左端，正味熱効率の棒の幅 $0$）．直した後は PASS（$0$ の線が左端から $34.5\ \text{px}$，正味熱効率の棒が $6.0$〜$40.5\ \text{px}$）．
* **段階 1**（`npm run verify`．C-4 の変更も含む作業ツリー）：全項目（$360 \times 640$）PASS 37/37，657 件中 FAIL 0 件，$796\ \text{s}$．画面のモード（$820 \times 1180$）PASS 21/21，225 件中 FAIL 0 件．性能の記録の上限超え 7 件と 3 件（判定しない）．
* 実際に熱効率が負になる運転で画面を撮って確かめてはいない．
