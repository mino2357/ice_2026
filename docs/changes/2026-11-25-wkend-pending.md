# 2026-11-25 Worker の計算を終えたとき，まだ写していない写しも捨てる

## 指示

利用者が先行版（ビルド `0e830642`）をスマートフォン（Android 17，SM-S947Q，claude.ai のアプリ）で全テストし，結果を貼った：PASS 36/37，672 件中 FAIL 1 件．FAIL は TEST-15 項目 22 の (c)「写しが 1 回届いた後に `wkEnd` で終えると，その後に届いた写しを使わない」（実測「写しまで 14 フレーム，変化 あり」）．

## 要件の差分

なし（REQ-15 の 17 (c)「`[中止]` の後に結果が届いても使わない」のとおりに直す）．

## 原因

`wkEnd` は計算を Worker の一覧から外して Worker に知らせるが，終える前に届いてまだ写していない写し（`o.wk.q`）を残していた．終えた後に `run` を呼ぶと，それを写した．スマートフォンは Worker が速く，検査の「最初の写しを写したフレーム」と「終える」の間に次の写しが届いた．開発用の計算機ではその間に届かず，FAIL にならなかった．

画面への影響：`[中止]` の後は，運転点のマップと VVT マップは `run` を呼ばない（`MP.run=null`，`done=true`）ので，画面の表示は変わらなかったと見る（推定）．

## 決めたこと

* `wkEnd` で `o.wk.q` も捨てる（SPEC-15 L の 6 に「終える前に届いてまだ写していない写し」を足した）．
* 検査（TEST-15 項目 22 (c)）を，端末の速さによらず確かめられる形にした：最初の写しを写した後，次の写しが届いて写していない状態になるのを待ってから終える．

## 検証の結果

* 直す前（検査だけを直した版）：開発用の計算機でも TEST-15 が FAIL した（「写していない写し あり，変化 あり」）．
* 直した後：TEST-15 の 40 件中 FAIL 0 件（「写していない写し あり，変化 なし」）．
* 段階 1（`npm run verify`）：全項目 635 件中 FAIL 0 件，画面のモード（$820 \times 1180$）228 件中 FAIL 0 件．
* 実機の全テストの総所要は $284.5\ \text{s}$（前に貼られたビルド `c62b261f` では $204.5\ \text{s}$）．テストごとの前の値が無いので，増えた原因（この間に足した検査か，Worker か）は分けていない．上限（$480\ \text{s}$）の中．
