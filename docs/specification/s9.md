## 9. 開発時検証 [D]

`npm test` は，文書とコードの整合を点検し，成果物をビルドし，ヘッドレス Chromium で次の 7 通りについてテストを実行する（SPEC-15 A.2，SPEC-20）．

| ビューポート | 入力 | 実行する項目 | MathJax |
| :--- | :--- | :--- | :--- |
| $360 \times 640$ | タッチ | 全項目 | 手元の版 |
| $384 \times 780$ | タッチ | 画面のモード | 手元の版 |
| $412 \times 915$ | タッチ | 画面のモード | 手元の版 |
| $384 \times 780$（極端な利用者状態．TEST-20 項目 4） | タッチ | 全項目 | 遮断 |
| $820 \times 1180$ | タッチ | 画面のモード | 手元の版 |
| $1180 \times 820$ | タッチ | 画面のモード | 手元の版 |
| $1440 \times 900$ | マウス | 画面のモード | 手元の版 |

全項目の 2 通りが 37/37 PASS，画面のモードの 5 通りが実行した全テストで PASS し，極端な利用者状態では実行の前後で状態が一致することを納品条件とする．画面のモード（SPEC-20 B の 9）は，画面の大きさによらない [A][S] の項目を 5 回繰り返さないためのもので，1 通りあたりの所要は全項目の約 5 分の 1 である（実測：全項目 $221.8$〜$227.5\ \text{s}$，画面のモード $39.8$〜$45.3\ \text{s}$，7 通りで $11.1$ 分）．MathJax は，手元の MathJax 3.2.2（`vendor/mathjax-3.2.2/es5/tex-svg.js`．環境変数 `MATHJAX` で場所を変えられる）を CDN の URL に振り向けて読み込み，極端な利用者状態では読み込みを遮断して TeX の表示で全テストを通す．

**検証の段階**（要件定義書 5.1 節）：上の 7 通り（`npm test`）を**段階 2** と呼び，正式版の公開の前にだけ実行する．ふだんの変更は**段階 1**（`npm run verify`）で確かめる．

1. 段階 1 は，検証の入力（`src/` のファイル，4 文書の断片，`tests/headless.js`，`tools/dev/run.js`）のハッシュを，前に検証が PASS したときの値（`verify.lock.json`）と比べ，変わったものから実行するテストを選ぶ．`src/tests.js` は，テストの関数（`TST[n]`）ごとと，それ以外に分けて比べる．変わったものが無ければ何も実行せず，前の結果を使う．
2. 選び方は，粗く，安全な側にする（どのテストに影響するかを細かく推し量らない）．

    | 変わったもの | 実行するもの |
    | :--- | :--- |
    | 4 文書の断片，`src/doc.js`，`src/build.py` | TEST-16（$360 \times 640$） |
    | `src/audio.js` | TEST-21，36 |
    | `src/tests.js` の `TST[n]` だけ | TEST-n |
    | `src/core.js`，`src/tests.js` のそれ以外 | 全項目（$360 \times 640$）．`src/core.js` は第25版とのビット単位の比較も |
    | `src/ui.js`，`src/plot.js`，`src/style.css`，`src/index.tpl.html`，`src/build.py` | 画面のモード（$360 \times 640$ と $820 \times 1180$） |

3. どの場合も，はじめに整合の点検（`npm run check`：整形，索引，文書とコードの整合，使っていない名前）とビルドを行う．
4. 段階 1 では性能の記録を判定しない（SPEC-20 B の 10）．段階 1 がすべて PASS すると `verify.lock.json` の段階 1 のハッシュを更新する．段階 2 がすべて PASS（終了コード 0）すると，段階 1 と段階 2 の両方を更新する．
5. 所要の目安（開発用の計算機．実測は `docs/changes/2026-11-21-structure.md`）：文書だけの変更は約 1 分，画面の変更は約 3 分，`src/core.js` の変更は約 7 分，段階 2 は約 15 分．
